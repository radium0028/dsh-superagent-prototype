# GitLab Source watches many Projects, executes in one

The GitHub Source binds a single repository that is both the origin of events and the target of execution (branches, pull requests, credentials). For the GitLab Source we split those roles: a deployment watches any number of Projects on one self-hosted instance, but workers clone, branch, and open merge requests in exactly one Execution Project, named explicitly in the Source configuration (like GitHub's repository field) and canonicalized through the projects API. The alternative — per-ticket execution in the originating project — was rejected for now because the execution environment (prepare, `$DSH_SUPERAGENT_DIR`, worker git config, environment variables) assumes a single repository; thread identity already carries the project path, so lifting this later stays possible. The GitLab Source is an optional source like Feishu: a broken configuration degrades only itself, while GitHub remains the mandatory source.
